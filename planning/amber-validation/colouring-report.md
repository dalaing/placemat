# Colouring allocator for Amber's large buffers (A269/A271): report
(Colouring agent, 2026-10-04; saved by the main session from its report. Fork scratchpad only; nothing in the amber checkout edited by the agent.)

**Result.** Colouring large blocks removes the L1 aliasing and the windows' two-speed switching, with nothing measurably slower once two hot-path costs are avoided. Main vs final build ($S/col/pq), 200 cases: geomean −4.19% (−4.29, −4.08); windows excluded −0.62% (−0.70, −0.55); also without qgroup −0.11% (−0.19, −0.04).

## 1. maxprior/minprior: alignment, not aliasing
The joint stage's "25-35% slower at some colours" was an artefact of its 16-byte colour steps: slow colours were all 16 or 48 mod 64, fast ones 0 or 32. `AL(x)` in a.h is `__builtin_assume_aligned(x,32)`; payloads at 16 mod 32 break it and vector stores split cache lines. Direct test (debug build, AMBER_COLSEQ): `|':wx` 1M longs, output at 16 mod 32: 20.6-21.0 ms; at 0 mod 32: 16.3-16.5; input also at 16 mod 32: 22.5-23.1. At 64-byte colours both kernels are flat over all 256 relative offsets mod 16 KB (and a finer pass near 0 mod 4 KB, 7 runs each): maxprior 16.3-16.6 ms, minprior 29.5-30.6. No 4K load/store aliasing band. Rule: keep payloads 64-byte aligned. Stage fix (applied by the main session, fc3725e4): COLOUR_STEP=64, no 16-byte term in the designed colours. The maxprior/minprior data flags in $S/ld/final came from this.

## 2. The policy
Blocks ≥64 KB (classes 10-23) get colour `64*((n*199) mod 256)` from a per-thread counter n (a Kronecker sequence over the 16 KB set stride; M=199: allocations 1-8 apart differ by ≥28 slots (1.8 KB) mod 16 KB and ≥7 slots (448 B) mod 4 KB — the x86 L1 stride). Taken from the block's existing spare room (reduced modulo the room when short; 0 under 64 B); stored in a spare header byte (−31); the header at the block's start also carries class and colour so the heap walk (`OBS`, `\m`, `bsm`) still steps block by block; `m0` moves the header back, so free lists and splitting only see uncoloured blocks; colour recovered from the header (works with 4 KB pages). Blocks <64 KB unchanged.
Two fixes over the first version (pa → pq): (1) fast paths: pa's extra work in `an`/`m0` on every allocation cost chardivfold +8.5%, dictplus +5.4%, jsonints +4.3% (reproduced by a zero-colour control build py); pq finishes large blocks out of line via a tail call (`anc`), and `m0`'s colour check sits inside its existing class test (`i>=CMIN` instead of `i>=24`); `an` keeps 4 extra instructions. (2) growth rule: the colour reduces `cap()`, so `aa()` growing a vector one item at a time re-picked the same class with no slack and copied several times per class (most of jsonints' +9.8%); now an owned coloured vector that would still fit uncoloured moves to the next class, as stock does at the class top.
Alternatives (29-case subset, pa code; main vs each): geomean counter −21.1%, block-index hash −21.4%, random −20.9%; windows and qgroup equal within ~3 points; maxprior/minprior noise in all; worst run-to-run max/min on windows ≤1.22 / ≤1.30 / up to 1.52. Counter chosen: deterministic within a run, relative offsets depend only on allocation distance, sweeps colours in a timing loop (averages rather than locking in luck); hash depends on the ASLR base across classes (a small lottery returns); random has a heavier tail.

## 4. Memory
No change of block class and no extra virtual memory (colour from spare room; reduced or 0 when short: 158 of 1542 large allocations in microbench-q). At most one extra 16 KB page touched per large block; the growth rule can move a growing vector up a class up to 16 KB early. Peak RSS main/final: bench.k 350.0/350.1 MB; bench-std 22.4/22.4; suite.k 685.2/685.5; groupby/vecarith/vecsum within 0.1 MB; qbench 95.9/99.4 (+3.6%, the largest).

## 6. Two-speed switching gone
From raw round times (each round a new process; p90/p10 of rounds over the variant median; $S/col/tools/twospeed.py): window cases main 1.4-2.6 (20-60 slow rounds of 203), coloured 1.03-1.14; mmin/mmax 1.03-1.17 in both. Pinned C2 still switches (1.5-2.7); C2 + colour (cq2) 1.03-1.11: purely data placement.

## 8. Upstream proposal (agent's view)
A271 plus a ~15-line src/m.c patch (counter policy, pq structure: out-of-line large path, colour check inside m0's class test, growth rule, heap walk), with timings vs main: windows 2-2.8x, qgroup 2.5x, nothing measurably slower, RSS ≤+3.6%. Before proposing: (a) check on x86 CI that 64-byte colours spread mod 4 KB there; (b) optionally make the class test compare `i` directly (2 instructions instead of 4); (c) write it in the maintainer's style without the policy switches (AMCOL==2/3/9, AMCOL_LOG); (d) colours must stay multiples of 64 (≥32) because of AL().
